# HandyAlliance — Чек-лист запуска (§36.1)

Статус: живой документ. Ведётся с Этапа 3, исполняется при переезде на
`handyalliance.com`. Основание: `docs/MASTER_SPEC.md` §36.1, §32, §33, §17.

Смысл документа: половина настроек проекта привязана к домену. Пока платформа
живёт на `handyalliance-platform.vercel.app`, каждая такая настройка сделана
«пока так», и делать их дважды бессмысленно. Поэтому переезд — это **один
заход**, а не десять мелких, и всё, что к нему привязано, копится здесь.

## 4. Почта — блокер пилота

Встроенный мейлер Supabase отдаёт единицы писем в час. Это не «мелкая
настройка на потом»: 2026-08-04 тест регистрации упёрся в
`over_email_send_rate_limit`, то есть на встроенной почте **пилот с живыми
пользователями невозможен** — часть людей просто не получит письмо
подтверждения и не поймёт, почему.

- [ ] Домен верифицирован в Resend (SPF, DKIM, DMARC).
- [ ] Custom SMTP прописан в Supabase Auth; встроенный мейлер больше не
      используется.
- [ ] Проверены все транзакционные письма: подтверждение регистрации,
      сброс пароля, magic link, приглашение staff.
- [ ] Настроен адрес отправителя на домене и обратный адрес, который читают.

Следствие для **Этапа 6** (§17, email-канал): канал строится сразу поверх
своего SMTP. Встроенный мейлер не закладывается даже как временная схема —
иначе лимит всплывёт ровно тогда, когда пойдут первые живые рассылки.
