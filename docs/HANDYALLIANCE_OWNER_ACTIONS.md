Статус: живой список. Здесь копится всё, что **не может сделать разработка** —
потому что требует доступа, денег, юридического решения или живого человека

## 1a. Нужен ключ для новой функции (пилот не блокирует)

Голосовая заметка при создании сметы (§16.3) — второй способ заполнить
описание для AI-черновика, рядом с уже работающим текстовым. Код смерджен и
выключен по умолчанию: без ключа кнопка честно отвечает «voice notes aren't
turned on yet», печатное описание и сам AI-черновик работают как раньше,
ничего не блокируется.

Чтобы включить: завести ключ у поставщика речь-в-текст (код по умолчанию
рассчитан на формат ответа OpenAI Whisper — `POST /v1/audio/transcriptions`,
`response_format: verbose_json`; другой провайдер с тем же форматом ответа
подключается той же переменной) и добавить в Vercel (все три окружения):

- `TRANSCRIBE_API_KEY` — ключ провайдера.
- `TRANSCRIBE_MODEL` — необязательно, по умолчанию `whisper-1`.

Не путать с `VOICE_PROVIDER_API_KEY` из `.env.example` — тот для голоса
телефонного ответчика (Retell, §15), другая функция и другой провайдер.

## 2. Проверки, которые может пройти только владелец

Разработка их выполнить не может: нужен человек, которому Google разрешает
пройти экран согласия.

### Полный цикл Google Sheets Sync (Этап 3)

Страница: `/en/app/settings/google` на production.

1. Создать работу → дождаться cron (до 5 минут) или нажать **Sync now**.
   Ожидается: строка в таблице; в колонке **HandyAlliance Link** адрес
   развёртывания, а не `handyalliance.com`; в **Read Me** поле **Last synced**
   с датой, а не «Not yet».
2. **Disconnect**. Ожидается: таблица **остаётся** в Google со всеми строками.
3. Создать работу при отключённом Google — она должна создаться нормально.
4. **Connect Google** заново. Ожидается: счётчик «Changes waiting to sync»
   больше нуля (backfill §14.5).
5. Дождаться cron. Ожидается: работа из шага 3 в таблице, а строки из шага 1
   **не задвоились** (сопоставление по UUID, §14.8).

Признаки провала, о которых стоит сообщить: после шага 2 таблица опустела;
после шага 4 счётчик остался 0; после шага 5 строки задвоились; ссылка ведёт
на `handyalliance.com`.

## 3. Ждёт переезда на домен

Всё собрано в `HANDYALLIANCE_LAUNCH_CHECKLIST.md`. Коротко: домен, env,
Supabase Auth URLs, Google redirect URI, ротация ключей (**кроме
`GOOGLE_TOKEN_ENCRYPTION_KEY`** — см. исключение там же), Stripe test → live,
GA4/Search Console, юридические тексты §32.

Один пункт отсюда стоит начать **раньше** самого переезда, а не в моменте:

### Google consent screen: Testing → Production

Пока экран в Testing, подключить Google могут только аккаунты из списка test
users. Проверка Google идёт **неделями**, поэтому начинать надо за 3–4 недели
до открытия регистрации — раздел 0 `HANDYALLIANCE_LAUNCH_CHECKLIST.md`.

## 6. Известное незакрытое в коде (не требует владельца)

- «Choose an existing sheet» — кнопка неактивна, нужен Google Picker.
- Табы §14.7 кроме Jobs/Customers/Read Me — появятся вместе с инструментами,
  которые их наполняют (Estimates — Этап 4, Calls — Этап 8 и так далее).
- Агрегаты клиента (Total Jobs, Total Revenue) — вместе с экраном клиентов
  §14.7.2; до тех пор колонки пустые, а не нулевые.
- Backfill ставит события пачкой, воркер берёт 200 за прогон: при импорте на
  тысячи работ разбор растянется по 5 минут на пачку.
- Шаблоны писем Supabase Auth для сброса пароля и приглашения staff — не
  сделаны специально: этих экранов ещё нет в продукте (нет формы «забыли
  пароль», нет приглашения staff по почте), и писать шаблон для несуществующей
  кнопки — писать вслепую. Появятся вместе с этими экранами, тем же приёмом,
  что confirmation/magic_link (§16.9, `docs/HANDYALLIANCE_ARCHITECTURE.md` §5i).

§14.7.7 (Read Me: время последней синхронизации) — если сверяетесь по этому
списку, он уже закрыт, реализован при доработке backfill/reconnect: воркер
пишет реальное время при каждой успешной синхронизации, а не один раз при
создании таблицы.
